# Plan: The room's message list (from specs/room-message-list.md, 2026-11-13)

Status: approved.

The room switches to the package's list. The reference's room (`59f6fe6f2a5`: `RoomMessageList`, `RoomMessageRow`,
`useRoomMessageListData`, `useRoomJumpTarget`) is copied and then adapted to the base; `RoomBody.tsx` is hand-merged from
`develop`'s file, not copied. Every answer of the spec gate is in the spec (Q1 to Q9). `develop` wins where it differs.

What the plan does not copy, or changes, against the reference:

- `RoomBody.tsx` keeps `develop`'s `useUserScrollIntent` input gate, `setHasUserReachedLatestMessageCallback`, `useCanPreviewRoom`,
  `useHandleUnread`, `useRoomMessages` from `hooks/`, `useTranslation` of `react-i18next` and the 300 ms debounce of the unread count.
  It drops `BubbleDate`, `useDateScroll`, `useGetMore`, `useHasNewMessages`, `useIsAtBottomRef`, `useKeepAtBottom`,
  `useMessageListNavigation`, the composer's dead `onResize`, the scrollbars wrapper and the two dead wrapper classes.
- `useRoomMessageListData` derives `restoredPosition` on every render from the first unread id and the listed messages (R12 to R14);
  `isOwnMessage` says no for a thread reply (R43); `isLoadingNewerMessages` as the reference.
- `useRoomJumpTarget` starts loading around the raw `msg` at once when nothing is loaded (R32) and asks for the target's messages only
  while nothing else loads.
- `RoomMessageRow` takes the four markers as booleans instead of the subscription object, `renderMessage` is stable (R52), and each
  row registers for "Select all" (R46), as `MessageListItem` did.
- `RoomMessageList` passes `deferPagingUntilInput`, the room's space at its ends (21px; 10px, or 34px while newer messages remain, where
  `develop` shortened the element around the list by 24px) and the height of what `RoomBody` draws over the top of the list, which
  `RoomBody` measures with a callback ref (R57, R60, R61; review round 1); `useRoomMessageListData` starts no page while the history
  manager loads one (R39).
- No `setAvailableMessages` on the selection store (intent Q1).
- The room is keyed by `RoomBodyContent`, a container in `body/layout/` with `develop`'s `main-content-flex` (the reference keys a raw
  `Box`), since `BubbleDateScope` is the thread's; the viewer's-input flag lives under that key (R26).

## Risks

- jsdom cannot lay out the virtualizer, so the room's specs run the package's list with `virtua`'s `Virtualizer` replaced (a one-line
  `jest.mock`) and a double for the handle; what scrolls stays proven by the package's play tests. The whole room is never run in a
  browser here: QA does the manual check (the scope's list).
- Read state is the most fragile: a double list cannot tell that the real list reports on its own. `getVisibility()` is asked
  synchronously, as `message-list` R57 promises; the spec drives the callbacks of the real manager (not a mock) so the gate is proven end to end.
- The reducer-level D3 is unreachable from the room (R42); the spec rejects `getMore` after the clear to keep it so.
- Q3 cannot be exact: the viewer's own thread reply that shows in the room raises "New messages" when reading above. Recorded in the spec.
- The e2e page object selector is changed unrun; QA lists it.
- If work stops after step 7 the list parts are unused and nothing changes for viewers; after step 8 the old list is dead code; stopping
  after step 9 leaves the history manager's dead DOM code (harmless).
- `oxlint --fix` rewrites `SelectedMessagesContext.tsx` and `lib/autotranslate/autotranslate.ts`; those edits stay out of every commit.
