# Shortcut Ledger: Agent Identity and Access

Each entry records one shortcut that the fastest path to delivery takes (DC-1). The next iteration resolves the open entries. Rules: [spec.md, DC-3](spec.md#dc-3-shortcut-ledger). Decisions: [research.md](research.md).

| ID | Requirements | Ships now | Limit | Risk | Fix in the next iteration | Status |
|----|--------------|-----------|-------|------|---------------------------|--------|
| SH-001 | FR-002, FR-006 | The agent badge ships in the web client. | Mobile and desktop clients do not show the badge yet. | Users on mobile or desktop cannot tell an agent from a human. | Ship the badge in the mobile and desktop clients. | Open |
| SH-002 | FR-052 | Each agent has one active credential. The owner or an admin can revoke it. | The platform does not detect two harness instances that share one credential. | A copied credential works in parallel until someone revokes it. | Record the IP and the `User-Agent` per call, and flag a switch inside a short window (RQ-2). Blocking needs MCP sessions. | Open |
| SH-003 | FR-036, FR-040 | The agent tool table leaves out spotlight, directory, autocomplete, and the user list. Agents find their rooms through `get_agents_me` and their members through `get_rooms_membersOrderedByRole`. | An agent cannot search for users or rooms by name. | Low: the agent can reach only its allowed rooms anyway. | Add agent-filtered variants that return only allowed rooms and their members. | Open |
| SH-004 | FR-023, edge case "creates a room or a discussion" | The agent tool table leaves out the tools that create rooms, discussions, and direct messages. | An agent cannot start a direct message or create a room, even when its owner could. | Low: the agent can still reply where a human starts the talk. | Add the create tools, and add each new room to the allow list when the scope allows room creation. | Open |
| SH-005 | FR-007 (paths), "Registration paths to evaluate" | RP-1 (MCP tool), RP-2 (OAuth consent), and RP-7 (REST) ship. They share one endpoint. RP-2 revokes the OAuth token after the registration (FR-056). | RP-3 (registration token), RP-4 (pending self-registration), RP-5 (admin form), and RP-6 (Apps Engine) do not ship. A headless agent with no browser needs a developer to run the registration once with their own PAT. The RP-2 consent page does not list the capabilities. The RP-2 token has full access as the human until a registration succeeds. The access token lasts 1 hour and the refresh token 2 weeks, the library defaults. Each refresh returns a new refresh token. | A client that never completes a registration and refreshes at least once every 2 weeks keeps full access as the human with no end date. | Ship RP-3. Add token scopes, so an RP-2 token reaches only the registration tool, and list the capabilities on the consent page. Re-evaluate RP-4 to RP-6 with demand data. | Open |
| SH-006 | FR-034, FR-049 | Agents learn of messages and decisions by polling `get_agents_messages` every 2 s, or by DDP subscriptions (FR-054). | No push over MCP: a harness that speaks only MCP must poll. | Polling load grows with the count of MCP-only agents. The latency floor is the poll interval. | Add a long-poll `wait` to `get_agents_messages` (A-1). | Open |
| SH-007 | FR-051 | The guard caps each agent at 300 calls per minute, counted in memory on each instance. | With N instances, an agent can make up to N × 300 calls per minute. The post limit (FR-050) is exact across instances. | A busy agent can load a multi-instance cluster more than intended. | Move the call counter to a shared store, or key it per agent in the shared rate limiter. | Open |
| SH-008 | FR-033 | A cron job marks expired approval cards every minute. A decision after expiry is refused at once. | The card can show the pending state for up to 60 s after its expiry. | A member sees buttons that no longer work for up to one minute. | Schedule an expiry job per card, or render the expiry on the client. | Open |

**Amendment A-1 (2026-11-19)**: SH-006 has a sized upgrade path, a long-poll `wait` on `get_agents_messages` that returns as soon as a message arrives. See [research.md, A-1](research.md#a-1-2026-11-19-long-poll-delivery-over-mcp). The entry stays open until F-9 ships.
